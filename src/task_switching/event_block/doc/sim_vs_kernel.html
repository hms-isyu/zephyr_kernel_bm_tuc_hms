z_swap prologue (measure_event_z_swap_overhead, SIM_Z_SWAP_PROLOGUE)

The half of the swap chain that runs before the thread leaves the CPU. The kernel pends PendSV just before dropping the interrupt mask; the simulation must not switch, so it omits that write and captures the stop counter at the same point.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Instructions in the windowkernel 12, simulation 10.
Known omissionstwo instructions, both shown in the table as one-sided rows inside the window. (1) sim_arch_swap_prologue() reproduces the kernel read-modify-write of SCB->ICSR with SCB->ICSR |= (0UL << SCB_ICSR_PENDSVSET_Pos), so the load and the store both have counterparts; only the orr.w at z_swap_irqlock +12 that actually sets the PENDSVSET bit has none, by design — pending PendSV would hand the CPU to the scheduler and the measurement would never close. (2) the isb sy at z_swap_irqlock +1e has no counterpart either: the kernel drops the mask through arch_irq_unlock(), which is __set_BASEPRI() followed by __ISB(), while sim_arch_swap_prologue() calls __set_BASEPRI(0) directly and captures the stop counter immediately after the msr. This one is not required by the no-switch constraint.
Off-path, excludedz_swap_irqlock +22..+28 and sim_z_swap_irqlock_prologue +22..+28 — the reload of arch.swap_return_value and the return, which belong to the tail, not the prologue.

Wait prologue (measure_wait_overhead, SIM_WAIT_PROLOGUE)

The half of k_event_wait_safe() that runs before the thread leaves the CPU: the wait conditions have failed, so the thread records what it is waiting for and descends through z_pend_curr() into the swap chain, ending at the msr BASEPRI where PendSV fires.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Instructions in the windowkernel 35, simulation 31.
Known omissionsthree instructions, all shown in the table as one-sided rows inside the window. Two are the z_swap_irqlock pair described in the swap-prologue table above: the orr.w at +12 that sets PENDSVSET (omitted by design) and the isb sy at +1e (not required by the no-switch constraint). The third is the ldr r0, [r0, #8] at z_pend_curr +1a, where the kernel dereferences _kernel for cpus[0].current and the simulation passes &_sim_current_thread as a literal.
Register allocation, not omitted workone instruction, the fourth one-sided row: mov r6, r3 at k_event_wait_internal +7e caches the thread pointer in a callee-saved register across the swap. The simulation keeps it on the stack and reloads it after the call, at sim_k_event_wait_internal +7e, which sits in the excluded tail — so that reload appears on neither side of the window.
Depth of the comparisonthe table compares the frames it names. sim_z_pend_curr_prologue() takes the spinlock and calls sim_pend_locked(), so it tracks z_pend_curr() instruction for instruction except the one load named above. What sits behind the bl still differs: sim_pend_locked() is a stub, so it does not enqueue on the wait queue or arm a timeout the way the kernel pend_locked() does.
Off-path, excludedk_event_wait_internal +00..+78 (entry, spinlock, reset arm, are_wait_conditions_met, the conditions-met and no-wait arms) and +94..+9c (the tail); sim_k_event_wait_internal +00..+4e and +7c..+8c; z_swap_irqlock +22..+28 and sim_z_swap_irqlock_prologue +22..+28.

No-wait tail (measure_wait_tail_no_wait_overhead)

A K_NO_WAIT wait whose conditions are not met returns immediately: the thread never pends, never reaches the scheduler, and the whole chain is the mask restore plus the return. There is no PendSV boundary on this path.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Instructions in the windowkernel 7, simulation 7 — no omissions, the two columns match one for one.
Compensated differenceone instruction. The kernel parks the return value in its callee-saved register inside the arm, at k_event_wait_internal +5e (mov r6, r0). In the simulation the compiler hoists the equivalent move above the branch, to sim_k_event_wait_internal_tail +2e, where it falls outside the window. A mov r0, r0 at +50 stands in its place, so the two windows hold the same instruction count and the same instruction classes.
Framesim_k_event_wait_internal_tail() carries r8 in its clobber list alongside r9–r11, so it pushes and pops the same nine registers k_event_wait_internal() does — that is what makes the ldmia.w at the end of the window, and the add sp ahead of it, cost the same.
Off-path, excludedk_event_wait_internal +00..+0e and +18..+54 (entry, spinlock, reset arm, are_wait_conditions_met), +62..+78 (the conditions-met arm) and +7a..+9c (the pend arm, covered by the wait prologue table); the shared epilogue at +10..+14 is in the window, rows 12–14. sim_k_event_wait_internal_tail +00..+34 and +54..+6a, with its epilogue at +6c..+70 in the window.

Build configuration

Compiler
arm-none-eabi-gcc 14.2.1 (Arm GNU Toolchain 14.2.rel1), ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb
Optimisation
-Og (CONFIG_DEBUG_OPTIMIZATIONS=y), -mcpu=cortex-m33 -mthumb -mabi=aapcs, -ffunction-sections -fdata-sections
Linker script
generated zephyr/linker.cmd for frdm_mcxn947/mcxn947/cpu0, CONFIG_XIP=n — text runs from RAM
Kernel config
CONFIG_SMP=n, CONFIG_USE_SWITCH=n, CONFIG_TRACING=n, CONFIG_ASSERT=n, CONFIG_TIMESLICING=n, CONFIG_EVENTS=y — the set asserted by sim_common.h
Extraction
arm-none-eabi-objdump -d --no-show-raw-insn, with call targets in relocatable objects resolved through objdump -r. Rows are named by (function, offset) and the text is read back from that output; literal pools are not shown.
Cost
Instruction counts only. Arm publishes no per-instruction cycle table for Armv8-M, so cost has to be measured differentially on the target.
