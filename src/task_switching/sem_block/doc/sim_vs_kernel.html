S_A: z_swap prologue (measure_sem_z_swap_overhead, SIM_Z_SWAP_PROLOGUE)

The half of the swap chain that runs before the thread leaves the CPU, entered from z_pend_curr() on the blocking k_sem_take(). The simulation captures the stop counter after the msr BASEPRI where the kernel takes PendSV.

Scope of this comparison
Importantthe kernel isb sy after the msr BASEPRI in z_swap_irqlock() has no counterpart in the simulated prologue, on purpose. It runs once per switch and is compensated in the tail, by SIM_INSTRUCTION_FLUSH() in sim_arch_swap_tail(). Adding it to the prologue would count it twice.
Belongs toS_A, the k_sem_take(&test_sem, K_FOREVER) of H_Task_SA. Kernel path: z_impl_k_sem_take(), z_pend_curr(), z_swap_irqlock() up to the msr BASEPRI where PendSV is taken. Simulated by sim_z_swap_irqlock_prologue().
Binariesboth sides from the linked build/zephyr/zephyr.elf; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 12, simulation 11; of the rows with both sides in the window, 10 sit at the same address modulo 4; row 9 differs: kernel 30003d8e, simulation 30001604.
Known omissionsone instruction, row 17: the orr.w at z_swap_irqlock +10 that sets PENDSVSET in the value stored back to SCB->ICSR. sim_arch_swap_prologue() writes SCB->ICSR |= (0UL << SCB_ICSR_PENDSVSET_Pos); the compiler removes an OR with 0, so the load and the store have counterparts and the orr.w has none.
Outside the windowthe isb sy at z_swap_irqlock +1c, row 21. The thread leaves the CPU at the msr BASEPRI and regains it on this isb (see event_preempt/doc/sim_vs_kernel.html), so it executes after PendSV returns.
Register allocationr2 and r3 swap roles between the two frames; widths and offsets are the same up to z_swap_irqlock +10, after which the simulation runs 4 bytes ahead (the missing orr.w).
Before the window, not shownz_pend_curr +00..+20 (lock, pend_locked, argument set-up).
Off-path, excludedz_swap_irqlock +20..+24 and sim_z_swap_irqlock_prologue +20..+24, the reload of arch.swap_return_value and the return, which belong to the tail.

S_A: give tail (measure_give_tail_overhead)

The half of the switch that runs after L_Task_SA regains the CPU: the return out of z_swap_irqlock() and the epilogues of reschedule(), z_reschedule() and z_impl_k_sem_give(), up to the stop capture.

Scope of this comparison
Belongs toS_A, the k_sem_give(&test_sem) of L_Task_SA that woke H_Task_SA in the previous iteration. L_Task_SA left the CPU inside it and regains it when H_Task_SA blocks. Kernel path, returning: z_swap_irqlock() from the PendSV return, reschedule(), z_reschedule(), z_impl_k_sem_give(), back to L_Task_SA. Simulated by sim_z_swap_irqlock_tail(), sim_reschedule_swap_tail(), sim_z_reschedule_swap_tail(), sim_z_impl_k_sem_give_tail().
Binariesboth sides from the linked build/zephyr/zephyr.elf; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 8, simulation 8; 8 rows with the same mnemonic, 0 of them differing only in register names; 7 rows at the same address modulo 4; row 15 differs: kernel 30005848, simulation 300046d6.
Kernel STOProw 18 is the S_A stop capture in L_Task_SA; the matching start capture is in H_Task_SA, before its k_sem_take(). L_Task_SA reloads the counter base from the literal pool first (row 17); the probe holds it in a register.
Before the window, not shownz_impl_k_sem_give +00..+44 (lock, unpend, ready, call set-up), reschedule +00..+16 (key test, IPSR test, ready-queue compare, the call); sim_z_impl_k_sem_give_tail +00..+08, sim_reschedule_swap_tail +00..+16, sim_z_swap_irqlock_tail +00..+06 (key store).
Off-path, excludedz_impl_k_sem_give +4a..+64, the no-waiter arm; reschedule and sim_reschedule_swap_tail +1c..+20 and +26..+2e, the no-swap arms.

S_B: no-wait tail (measure_take_tail_no_wait_overhead)

A K_NO_WAIT take on an empty semaphore: the thread never pends and never reaches the scheduler. The tail is the mask restore, the -EBUSY return value and the return. There is no PendSV boundary on this path.

Scope of this comparison
Belongs toS_B, the k_sem_take(&test_sem, K_NO_WAIT) of H_Task_SB. Kernel path: z_impl_k_sem_take(), K_NO_WAIT arm, from the mask restore to the return. Simulated by sim_z_impl_k_sem_take_tail().
Binariesboth sides from the linked build/zephyr/zephyr.elf; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 6, simulation 6; 6 rows with the same mnemonic, 0 of them differing only in register names; 6 rows at the same address modulo 4.
Branch into the armbeq.n at z_impl_k_sem_take +2c jumps over 3000382e..3000383b, 6 instructions not executed (the pend arm); beq.n at sim_z_impl_k_sem_take_tail +2c jumps over 3000158e..3000159b, 6 instructions not executed. Both branches sit before the window.
Kernel STOProw 15 is the S_B stop capture in H_Task_SB; the matching start capture sits before the call, outside this table.
Stop capture widthrow 15: the probe holds the counter base in r9 and reads with ldr.w (32-bit); H_Task_SB holds it in r4 and reads with ldr (16-bit). Both start on a word boundary.
Before the window, not shownz_impl_k_sem_take +00..+14 and +28..+2c, the same ranges in sim_z_impl_k_sem_take_tail (entry, lock, count test, timeout test): 10 instructions, identical text.
Off-path, excluded+16..+22 in both takes, the count-available arm; +2e..+3a, the pend arm.

Build configuration

Compiler
arm-none-eabi-gcc 14.2.1 (Arm GNU Toolchain 14.2.Rel1), ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb
Optimisation
-Og (CONFIG_DEBUG_OPTIMIZATIONS=y), -mcpu=cortex-m33 -mthumb -mabi=aapcs, -ffunction-sections -fdata-sections
Linker script
generated zephyr/linker.cmd for frdm_mcxn947/mcxn947/cpu0, CONFIG_XIP=n: text runs from RAM
Kernel config
CONFIG_USE_SWITCH=n, CONFIG_TRACING=n, CONFIG_ASSERT=n, CONFIG_TIMESLICING=n, CONFIG_EVENTS=y, CONFIG_TICKLESS_KERNEL=n, CONFIG_THREAD_CUSTOM_DATA=n
Test
CONFIG_BENCHMARK_TEST_TASK_SWITCHING_SEM_BLOCK=y, TEST_CASE_II
Frame aliases
probe: measure_sem_z_swap_overhead or measure_take_tail_no_wait_overhead; pend: z_pend_curr; swap: z_swap_irqlock or sim_z_swap_irqlock_prologue (the copy at 300014a4, the call target of 30001604); take: z_impl_k_sem_take or sim_z_impl_k_sem_take_tail; hsb: H_Task_SB; resched: reschedule or sim_reschedule_swap_tail; z_resched: z_reschedule or sim_z_reschedule_swap_tail; give: z_impl_k_sem_give or sim_z_impl_k_sem_give_tail; lsa: L_Task_SA; in the give tail swap is sim_z_swap_irqlock_tail (the copy at 300014dc) and probe is measure_give_tail_overhead
Extraction
arm-none-eabi-objdump -d --no-show-raw-insn on the linked ELF. Rows are named by address and the text is read back from that output; objdump comments and literal pools are not shown.
Path
From the binary: instructions, addresses, branch targets, the arms that exist. Assumed: the beq.n at +2c of both takes is taken (test_sem and tail_sem hold a zero count, timeout K_NO_WAIT); the swap chain is entered from z_pend_curr on the blocking take; in the give tail, reschedule takes its swap arm (H_Task_SA is ready and outranks L_Task_SA) and L_Task_SA resumes at the isb after the msr BASEPRI where it left the CPU. Not measured: this page is a reconstruction from the listing, not a recording on hardware.
Cost
Instruction counts only. Arm publishes no per-instruction cycle table for Armv8-M, so cost has to be measured differentially on the target.
