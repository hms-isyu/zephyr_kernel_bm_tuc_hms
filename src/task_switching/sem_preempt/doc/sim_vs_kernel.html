One table per measurement that zephyr_sim.c in this folder provides: for S_B the tail of k_sem_give() without a switch, in both arms; for S_A the tail of k_sem_take() after the switch and the swap prologue. Reconstruction from the linked listing, not a recording.

S_B: give tail, waiter (measure_give_tail_no_swap_overhead, has_waiter = 1)

The woken waiter does not outrank the giver, so reschedule() takes its no-swap arm. The give reaches the scheduler through the public z_reschedule() wrapper, which the simulation reproduces as its own frame.

Scope of this comparison
Belongs toS_B, cases with TEST_SB_HAS_WAITER = 1 (TEST_CASE_I, TEST_CASE_III): the k_sem_give(&test_sem) of H_Task_SB while the lower-priority L_Task_SB waits. Kernel path, returning: reschedule() from the irq_unlock() of its no-swap arm, z_reschedule(), the waiter arm of z_impl_k_sem_give(), back to H_Task_SB. Simulated by sim_reschedule_no_swap_tail(), sim_z_reschedule_no_swap_tail(), sim_z_impl_k_sem_give_tail(), run with has_waiter = 1.
Binariesboth sides from the linked build/zephyr/zephyr.elf of the TEST_CASE_I build; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 5, simulation 5; 5 rows with the same mnemonic, 0 of them differing only in register names; row 13 at a different address modulo 4 (kernel 30003a20, simulation 30001606).
Kernel STOProw 14 is the S_B stop capture in H_Task_SB; the matching start capture sits before the call, outside this table.
Branch into the armbeq.n at reschedule +14 jumps over 30003c7e..30003c83 (the swap call): the ready-queue cache still holds H_Task_SB. sim_reschedule_no_swap_tail reaches its arm the same way at +14.
Before the window, not shownz_impl_k_sem_give +00..+44 (lock, unpend, ready, call set-up); reschedule +00..+14; sim_z_impl_k_sem_give_tail +00..+22; sim_reschedule_no_swap_tail +00..+14. The simulation does not unpend or ready a thread; that work sits before the window.
Off-path, excludedreschedule +26..+2e, the key-non-zero arm; the swap arm on both sides.

S_A: take tail after the switch (measure_take_tail_overhead)

This window cannot be opened in the kernel: it would have to open inside the context switch. The thread leaves the CPU at the msr BASEPRI in z_swap_irqlock() and regains it on the following isb. The simulation starts its counter at that point and runs the same return chain back out.

Scope of this comparison
Belongs toS_A: the k_sem_take(&test_sem, K_FOREVER) of H_Task_SA, which pended in the previous iteration and regains the CPU when L_Task_SA gives. Kernel path, returning: z_swap_irqlock() from the PendSV return, z_pend_curr(), the pend arm of z_impl_k_sem_take(), back to H_Task_SA. Simulated by sim_z_swap_irqlock_tail(), sim_z_pend_curr_swap_tail(), sim_z_impl_k_sem_take_swap_tail().
Binariesboth sides from the linked build/zephyr/zephyr.elf of the TEST_CASE_I build; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 8, simulation 8; 8 rows with the same mnemonic, 0 of them differing only in register names; every row at the same address modulo 4.
Kernel STOProw 19 is the S_A stop capture in H_Task_SA; the matching start capture is in L_Task_SA, before its k_sem_give(). H_Task_SA reloads the counter base from the literal pool first (row 18); the probe holds it in a register and reads with ldr.w.
Before the window, not shownz_impl_k_sem_take +00..+36 and sim_z_impl_k_sem_take_swap_tail +00..+36 (entry, lock, count test, timeout test, pend call); z_pend_curr +00..+22 (lock, pend_locked, call); sim_z_pend_curr_swap_tail +00..+04; z_swap_irqlock +00..+18, the prologue, its own table.
Off-path, excludedthe count-available and no-wait arms of both takes.

S_A: z_swap prologue (measure_sem_z_swap_overhead, SIM_Z_SWAP_PROLOGUE)

The half of the swap chain that runs before the thread leaves the CPU, entered from the swap arm of reschedule() on the give of L_Task_SA. The simulation captures the stop counter after the msr BASEPRI where the kernel takes PendSV.

Scope of this comparison
Belongs toS_A: the k_sem_give(&test_sem) of L_Task_SA, which wakes the higher-priority H_Task_SA and switches. Kernel path: z_impl_k_sem_give(), z_reschedule(), the swap arm of reschedule(), z_swap_irqlock() up to the msr BASEPRI where PendSV is taken. Simulated by sim_z_swap_irqlock_prologue().
Binariesboth sides from the linked build/zephyr/zephyr.elf of the TEST_CASE_I build; addresses are linked addresses, so the 4-byte alignment of every instruction is the one the target executes.
Instructions in the windowkernel 12, simulation 11; 11 rows with the same mnemonic, 9 of them differing only in register names; row 9 at a different address modulo 4 (kernel 30003c7e, simulation 30001680).
Known omissionsone instruction, row 17: the orr.w at z_swap_irqlock +10 that sets PENDSVSET in the value stored back to SCB->ICSR. sim_arch_swap_prologue() writes SCB->ICSR |= (0UL << SCB_ICSR_PENDSVSET_Pos); the compiler removes an OR with 0, so the load and the store have counterparts and the orr.w has none.
Importantthe kernel isb sy after the msr BASEPRI in z_swap_irqlock() has no counterpart in the simulated prologue, on purpose. It runs once per switch and is compensated in the tail, by SIM_INSTRUCTION_FLUSH() in sim_arch_swap_tail(). Adding it to the prologue would count it twice.
Outside the windowthe isb sy at z_swap_irqlock +1c, row 21: the thread regains the CPU on it, so it belongs to the tail of the thread that switched out.
Before the window, not shownreschedule +00..+14 (key test, IPSR test, ready-queue compare).
Off-path, excludedz_swap_irqlock +20..+24 and sim_z_swap_irqlock_prologue +20..+24, the reload of arch.swap_return_value and the return, which belong to the tail.

Build configuration

Compiler
arm-none-eabi-gcc 14.2.1 (Arm GNU Toolchain 14.2.Rel1), ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb
Optimisation
-Og (CONFIG_DEBUG_OPTIMIZATIONS=y), -mcpu=cortex-m33 -mthumb -mabi=aapcs, -ffunction-sections -fdata-sections
Linker script
generated zephyr/linker.cmd for frdm_mcxn947/mcxn947/cpu0, CONFIG_XIP=n: text runs from RAM
Kernel config
CONFIG_USE_SWITCH=n, CONFIG_TRACING=n, CONFIG_ASSERT=n, CONFIG_TIMESLICING=n, CONFIG_EVENTS=y, CONFIG_TICKLESS_KERNEL=y, CONFIG_THREAD_CUSTOM_DATA=n, CONFIG_POLL=n
Test
CONFIG_BENCHMARK_TEST_TASK_SWITCHING_SEM_PREEMPT=y, TEST_CASE_I
Frame aliases
probe: the measure_* function named in each table; resched: reschedule or sim_reschedule_no_swap_tail; z_resched: z_reschedule or sim_z_reschedule_no_swap_tail; give: z_impl_k_sem_give or sim_z_impl_k_sem_give_tail; take: z_impl_k_sem_take or sim_z_impl_k_sem_take_swap_tail; pend: z_pend_curr or sim_z_pend_curr_swap_tail; swap: z_swap_irqlock, sim_z_swap_irqlock_tail (30001510) or sim_z_swap_irqlock_prologue (300014d8); hsa: H_Task_SA; hsb: H_Task_SB
Extraction
arm-none-eabi-objdump -d --no-show-raw-insn on the linked ELF. Rows are named by address and the text is read back from that output; objdump comments and literal pools are not shown.
Path
From the binary: instructions, addresses, branch targets, the arms that exist. Assumed: in S_B, reschedule takes its no-swap arm (L_Task_SB does not outrank H_Task_SB) or the give finds no waiter, per TEST_SB_HAS_WAITER; in S_A, reschedule takes its swap arm (H_Task_SA outranks L_Task_SA) and H_Task_SA resumes at the isb after the msr BASEPRI where it left the CPU. Not measured: this page is a reconstruction from the listing, not a recording on hardware.
Cost
Instruction counts only. Arm publishes no per-instruction cycle table for Armv8-M, so cost has to be measured differentially on the target.
