event_preempt — simulation vs kernel

One table per measurement that zephyr_sim.c in this folder provides. S_A blocks in k_event_wait_safe() and is woken by a preempting post; S_B posts with no matching waiter and never reaches the scheduler.

S_B — post-event tail (measure_event_tail_overhead)

No matching waiter, so k_event_post_internal() wakes nobody and reschedule() takes its no-swap arm. The post reaches the scheduler through the public z_reschedule() wrapper, so the chain carries one extra frame — which the simulation reproduces.

S_A — wait tail after the IRQ (measure_wait_overhead, SIM_WAIT_TAIL)

This window cannot be opened in the kernel: it would have to open inside the context switch. The thread leaves the CPU at the msr BASEPRI in z_swap_irqlock() and regains it on the following isb. The simulation starts its counter at that point and runs the same return chain back out.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Notethe kernel isb at z_swap_irqlock +1e is the second half of its irq_unlock, executed after the thread comes back. The simulation matches it with the explicit SIM_INSTRUCTION_FLUSH() that follows its counter capture.

S_A — z_swap prologue (measure_event_z_swap_overhead, SIM_Z_SWAP_PROLOGUE)

The half of the swap chain that runs before the thread leaves the CPU: the key is stored, -EAGAIN is parked in the return slot, and the interrupt mask is dropped. The kernel pends PendSV just before dropping the mask; the simulation must not switch, so it omits that write and captures the stop counter at the same point instead.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Known omissionstwo instructions. sim_arch_swap_prologue() reproduces the kernel read-modify-write of SCB->ICSR with SCB->ICSR |= (0UL << SCB_ICSR_PENDSVSET_Pos), so the load and the store both have counterparts; the orr.w at z_swap_irqlock +12 that actually sets the PENDSVSET bit has none, by design — pending PendSV would hand the CPU to the scheduler and the measurement would never close. The isb at +1e has none either: the kernel unlocks through arch_irq_unlock(), which is __set_BASEPRI(key) followed by barrier_isync_fence_full(), while the simulation calls __set_BASEPRI(0) alone. Both are shown in the table, inside the window, as one-sided rows.
Off-path, excludedz_swap_irqlock +22..+28 and sim_z_swap_irqlock_prologue +22..+28 — the reload of arch.swap_return_value and the return, which belong to the tail, not the prologue.

Build configuration

Compiler
arm-none-eabi-gcc 14.2.1 (Arm GNU Toolchain 14.2.rel1), ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb
Optimisation
-Og (CONFIG_DEBUG_OPTIMIZATIONS=y), -mcpu=cortex-m33 -mthumb -mabi=aapcs, -ffunction-sections -fdata-sections
Linker script
generated zephyr/linker.cmd for frdm_mcxn947/mcxn947/cpu0, CONFIG_XIP=n — text runs from RAM
Kernel config
CONFIG_SMP=n, CONFIG_USE_SWITCH=n, CONFIG_TRACING=n, CONFIG_ASSERT=n, CONFIG_TIMESLICING=n, CONFIG_EVENTS=y — the set asserted by sim_common.h
Extraction
arm-none-eabi-objdump -d --no-show-raw-insn, with call targets in relocatable objects resolved through objdump -r. Rows are named by (function, offset) and the text is read back from that output; literal pools are not shown.
Cost
Instruction counts only. Arm publishes no per-instruction cycle table for Armv8-M, so cost has to be measured differentially on the target.
