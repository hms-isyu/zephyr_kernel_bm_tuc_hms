S_B — resume tail (measure_thread_resume_tail)

reschedule() takes its no-swap arm and returns straight out. z_impl_k_thread_resume() calls the static reschedule() directly, not the public z_reschedule() wrapper, so the chain is two frames deep — which the simulation matches.

S_A — swap prologue (measure_swap_prologue_overhead)

S_A resumes a higher priority thread so reschedule() takes its swap arm; S_B resumes a lower priority one and takes the no-swap arm. Everything ahead of that branch is common to both and cancels in S_A − S_B, so the only prologue term left is the swap chain itself, from entry to the irq_unlock() where PendSV fires.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Known omissionone instruction. sim_arch_swap_prologue() reproduces the kernel read-modify-write of SCB->ICSR with SCB->ICSR |= (0UL << SCB_ICSR_PENDSVSET_Pos), so the load and the store both have counterparts; only the orr.w at z_swap_irqlock +12 that actually sets the PENDSVSET bit has none, by design — pending PendSV would hand the CPU to the scheduler and the measurement would never close. It is shown in the table, inside the window, as a one-sided row.

S_A — suspend tail (measure_thread_suspend_tail)

H_Task suspends itself, so z_impl_k_thread_suspend() takes its self-suspend arm and swaps directly through z_swap() — no reschedule() in this chain. The thread leaves the CPU at the msr BASEPRI inside z_swap_irqlock(), and S_A stops its counter the moment it comes back. Only this return half can be reproduced: the kernel cannot time it, because the window would have to open inside the context switch.

Scope of this comparison
Binarieskernel side from the linked build/zephyr/zephyr.elf; simulation side compiled standalone with the same command the build uses; its addresses are section-relative rather than linked.
Off-path, excludedz_impl_k_thread_suspend +00..+9a — the whole prologue: the current-thread test, the spinlock, z_mark_thread_as_suspended(), z_metairq_preempted_clear(), dequeue_thread() and update_cache(), plus the entire not-self arm (+0x0e..+0x4c and +0xa4..+0x14c) that this scenario never takes; z_swap_irqlock +00..+18, which is the prologue half.
Notethe simulation carries the same r3..r9 clobber so its frame pushes and pops the identical register set — that is what makes the ldmia.w cost the same.

Build configuration

Compiler
arm-none-eabi-gcc 14.2.1 (Arm GNU Toolchain 14.2.rel1), ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb
Optimisation
-Og (CONFIG_DEBUG_OPTIMIZATIONS=y), -mcpu=cortex-m33 -mthumb -mabi=aapcs, -ffunction-sections -fdata-sections
Linker script
generated zephyr/linker.cmd for frdm_mcxn947/mcxn947/cpu0, CONFIG_XIP=n — text runs from RAM
Kernel config
CONFIG_SMP=n, CONFIG_USE_SWITCH=n, CONFIG_TRACING=n, CONFIG_ASSERT=n, CONFIG_TIMESLICING=n, CONFIG_EVENTS=y — the set asserted by sim_common.h
Extraction
arm-none-eabi-objdump -d --no-show-raw-insn, with call targets in relocatable objects resolved through objdump -r. Rows are named by (function, offset) and the text is read back from that output; literal pools are not shown.
Cost
Instruction counts only. Arm publishes no per-instruction cycle table for Armv8-M, so cost has to be measured differentially on the target.
